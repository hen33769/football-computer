# 订单筛选汇总与投注日期吸附 Research

日期：2026-08-24

## 需求理解

- 订单页汇总区把现有“筛选投入”改为“已支付”，明确该金额只包含当前筛选结果中的已支付订单。
- 在“已支付”左侧新增“筛选总额”，统计当前筛选结果中全部订单的投入，不受支付状态影响。
- 投注页的日期折叠标题在向上滚动到固定页头下方时保持吸附，日期切换时由下一组标题自然替换。
- 吸附标题使用页面背景色，避免比赛卡片滚动时透到日期文字和操作按钮后方。

## 当前实现

### 订单筛选汇总

- `app/FootballApp.tsx` 通过 `orderLedgerTotals(filteredSavedSlips)` 取得筛选金额，并把 `expense` 渲染为“筛选投入”。
- `app/imports.ts` 中 `orderLedgerTotals().expense` 只累加 `paymentStatus === "paid"` 的订单投入，因此现有数值语义实际是“已支付”，不是所有筛选订单的总投入。
- 当前汇总顺序是“筛选结果 / 筛选投入 / 筛选盈亏 / 说明”。“筛选盈亏”以已支付支出和已结账收入计算，口径正确，不应改成全部订单总额。
- `app/globals.css` 的 `.order-filter-summary` 使用四列网格；新增金额后需要扩为五列，手机断点继续使用两列网格。

### 投注日期分组

- `app/FootballApp.tsx` 按日期把比赛渲染为 `.date-group`，组头 `.date-divider` 同时承载日期、场次数、复制和收起/展开操作。
- `app/globals.css` 的 `.date-divider` 当前只有普通 flex 布局，没有 `position: sticky`、顶部偏移、层级或不透明背景。
- 全局 `.hero-header` 是固定页头；滚动完成后高度约为 60px，层级为 1000。日期组头应吸附在它的下方，而不是页面视口的 `top: 0`。
- 页面背景由 `--canvas` 定义，`html` 和 `body` 都使用该变量，适合作为日期组头底色。

## 实现约束与风险

- “筛选总额”必须复用 `calculateStake`，保持串关、倍数和投注项计算口径与订单卡片一致。
- “已支付”继续使用账本支出口径；未支付订单不能计入筛选盈亏。
- 日期组头必须低于固定页头、但高于比赛卡片；否则会被页头遮挡或仍与卡片叠字。
- sticky 元素应留在各自 `.date-group` 内，让浏览器在组末自然推出旧日期标题，不需要新增滚动监听或 React 状态。
- 本次不改接口、D1、订单持久化或支付流程；实现完成后开发者另行要求提交、推送和部署，因此发布时按行为调整升级 minor 版本，并明确跳过无关的远端 D1 迁移与订单重写。

## 预计影响文件

- `app/imports.ts`：增加全部订单投入汇总函数。
- `app/FootballApp.tsx`：计算筛选总额，调整汇总标签、顺序和盈亏提示。
- `app/globals.css`：扩展订单汇总网格并为日期标题增加 sticky、层级和页面底色。
- `tests/calculator.test.ts`：验证筛选总额与已支付支出的不同统计口径。

## 验证重点

- 同时存在未支付和已支付订单时，“筛选总额”包含两者，“已支付”只包含后者，筛选盈亏仍只扣除已支付金额。
- 桌面端和手机端汇总项不溢出、不挤压说明文字。
- 日期标题滚到固定页头下方后保持可见，下一日期组到达时正确替换。
- 展开和折叠状态都保留吸附、复制和收起/展开交互，比赛卡片不会透过日期标题底色。
