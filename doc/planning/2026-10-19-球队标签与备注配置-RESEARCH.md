# 球队标签与备注配置 Research

日期：2026-10-19。当前仅 Research，待需求结论确认后再进入 Planning 与实现。

## 需求理解

- 设置页新增球队标签配置，例如「26 欧冠」，维护所属球队、标签底色、卡片短文案及可选生效日期范围。
- 赛事卡片通过现有球队别称识别球队，在主名与别称之间显示方形圆角标签；短文案未填时取标签名称首个字符。
- 悬停显示标签全名和球队备注，并能从卡片入口编辑该标签下的球队备注。
- 未设置日期范围表示长期生效。已确认标签内提供日期参照选择字段「当前日期 / 比赛日期」，默认当前北京时间日期。
- 已确认标签及备注为个人配置、个人使用；提供分享按钮生成字符串分享码，其他账号通过导入按钮导入标签配置。
- 已确认备注属于单个标签中的球队，跨标签互不影响；同标签新增重复球队必须考虑当前别称关系，发现重复时中断并提醒。
- 已确认后续修改别称造成既有成员归为同队时合并展示其备注，分行保留，不覆盖丢弃；每份备注末尾有编辑 icon，点击仅该份备注转为输入框。
- 已确认同队多个有效标签都参与展示，直接显示前 3 个，其余显示 +N；hover +N 显示该队全部有效标签及备注（包括已露出的 3 个）。
- 已确认「球队标签配置」和管理员维护的「队伍信息配置」是两个独立设置卡片、独立数据与保存流程；标签配置只读取队伍信息作为联想建议和别称匹配依据。
- 标签内新增队伍使用带建议的输入框，建议项来自队伍信息配置并可按别称搜索；用户也可以直接添加未配置的手填队名。
- 两个设置卡片各自点击新增时自动展开；球队标签支持显式删除并同时删除该标签下的个人成员备注，不影响公共队伍信息。

## 更新后的数据与接口方向

命名「球队标签配置」，所有登录用户均可管理自己的标签，无须 admin。允许一队多标签，使用公共队伍别称辅助匹配，但不修改公共别称。原先「只选已配置队伍组」的建议被用户补充场景替代：应支持直接输入队名，已有组可搜索选择，未建别称组的名称也能保存，以支持先建标签、后补别称。不做模糊匹配自动归队。

建议新增个人标签表（id/userId/name/shortText/color/dateBasis/startDate/endDate/displayOrder/revision/updatedAt）与成员表（id/tagId/sourceName/sourceNameKey/teamGroupId?/note/revision/updatedAt）。成员使用稳定独立 ID，保留原始名称和备注；teamGroupId 只作可失效的关联提示，不能成为唯一解析依据，也不因公共组删除级联删除私人备注。名称编辑后原始名称仍可追溯；彻底移除旧别称时的回退见下文。

通过 `/api/users/me/team-tags` 提供列表、增删改与导入等私有能力，成员备注按 tagId/memberId 单独更新。服务端从会话取得 userId，所有查询与写入限制当前账号；不能仅验证父标签或仅靠前端隐藏；请求不得接受客户端指定归属账号。所有响应（含错误）private/no-store，不启用公开跨域读取。标签不写入 MatchItem、订单快照、共享比赛缓存、公开别称响应或个人比赛备注表。账号切换/退出清除映射与草稿，忽略旧请求。API 名称及字段在 Planning 定稿。

标签及成员备注分开 PATCH，强制 expectedRevision，避免从卡片保存备注时回写整个标签或整个别称组。结构修改和成员删除需考虑未完成的备注编辑版本，不可用旧设置草稿覆盖新备注。前端按 tagId/memberId 更新所有相关卡片，防止较早 GET 覆盖较新 revision。

dateBasis 提供「当前日期」「比赛日期」两个明确选项，已确认默认当前日期。日期使用 Asia/Shanghai 自然日，包含起止两日；允许单端范围，空端点表示无界，拒绝非法或倒序日期。当前日期模式在北京时间跨零点重新计算；比赛日期模式使用开赛时间对应的北京时间自然日，不混用竞彩业务日。无日期范围时模式不影响生效；有范围而比赛时间无效时建议不展示并提示数据异常，不默认为当前日。

删除标签只删除当前账号该标签及成员；不影响公共队伍、比赛、订单。过期仅隐藏，不删除备注。新增迁移，不修改旧迁移，不回填比赛/订单。

## 别称去重与后续合并规则

建议统一解析函数供前端预检、服务端校验、导入预检和赛事卡片使用：先按 normalizeTeamName 标准化，若名称在当前别称索引命中则得到 group:<id>，否则为 name:<标准化名>。比赛队名使用相同规则；未知名称可以标准化精确命中，不需要公共别称组才能展示标签。

1. **新增时已重复**：在同一标签范围，对输入成员及现有成员按当前解析身份校验；a 与 b 已知同组则整体拒绝本次新增/导入的该配置并明确指出名称，不静默去重，不丢备注。跨标签允许同队。服务端必须重新校验，不能只靠浏览器。成员同名也需数据库 tagId/sourceNameKey 唯一约束兜底。
2. **保存后别称变更**：a、b 原本不同，后来解析到同组，只在展示层归为一队；同一标签只渲染一个 tag，下面依成员原顺序换行显示所有非空备注，保留 memberId；相同备注也不擅自删除。建议每行附轻量来源队名，区分来自 a 或 b。空备注仍有「暂无备注」编辑入口，以便新增该成员备注。
3. **编辑与拆分**：每份备注末尾编辑 icon 只修改对应 memberId，不把拼接后的文字回写到任一成员；另一行及其他标签均不改变。后续别称拆开可重新分别展示，各备注归属保持原样。设置页展示同样的合并视图/来源，删除某个来源成员应明确，不默认删除整组。
4. **身份随别称变化**：优先按 sourceName 当前归属解析；原名已从所有别称中移除时，可回退到仍存在的原 teamGroupId 保持关联；组也删除时回退原始标准化名称。若原名被移动到新组，应以新归属为准，不能固定旧 groupId。这种规则避免旧组删除误删私人数据，也允许 a/b 后补别称自然汇合。
5. **已合并历史数据的后续操作**：读取/改备注不因历史重复失败；编辑标签颜色/日期等非成员字段也不阻断。新增成员只拦截新造成的重复，不能要求用户先删除已合并的历史来源记录；全新创建/导入则严格去重。移除成员不会自动合并其备注。
6. **一致性与并发**：别称公共配置可能由管理员同时更新。普通校验与写成员分开会存在竞态；应在 Planning 明确如何检测别称快照变化并重试/409，或在 D1 同一事务内完成最终校验与写入。展示层仍必须容忍之后发生的合法别称合并。不得为了私人标签去重而批量改写所有用户数据。

公共别称读取失败时不能将所有队伍视为互不相关并允许新增；建议可展示已加载标签，但暂停依赖别称的新增/导入并提供重试。已挂载页面也要有重新读取别称的入口/时机，确保公共组调整后不长期保持旧解析；刷新、重新进入及提交前校验至少覆盖。

## 已确认的后端限时分享码流程

仅单标签分享。点击分享按钮调用后端接口，后端生成限时分享码并返回前端；接收用户在导入入口输入分享码，通过新的后端接口把该标签配置保存到当前账号。保存成功后前端重新请求个人标签列表，更新设置页及赛事卡片。此前自包含配置字符串方案已被替代。

建议接口形态：

- `POST /api/users/me/team-tags/[tagId]/shares`：登录后校验标签归属，读取已保存配置，生成分享快照与随机分享码，返回 `{ code, expiresAt }`。建议携带 expectedRevision，设置页有未保存草稿时提示先保存，避免分享内容与眼前草稿不一致。
- `POST /api/users/me/team-tags/import`：请求 `{ code, requestId }`，服务端依据会话取得接收账号，校验分享码存在、未过期、快照版本和字段有效、当前别称关系下无重复成员，再事务创建新标签及成员；返回新标签 ID。requestId 用于网络重试幂等，避免请求已成功但响应丢失导致重复创建。
- 导入成功后重新 GET 个人标签配置；保存成功但刷新列表失败应提示「已导入，列表刷新失败，请重试刷新」，不能误报导入失败并再次落库。接口错误保留输入码；导入中禁用重复提交。

建议快照包含生成时的标签全名、短文案、颜色、日期参照/范围、成员原始名称及各自备注。快照固定，不随分享者后续编辑变化；接收后是独立新 ID，双方不联动，也不按同名覆盖。分享按钮旁明确说明分享包含球队备注；目前没有用户要求排除备注，先按完整标签配置处理，不新增未要求的开关。

新增分享存储表，建议字段为 id、codeHash（唯一）、ownerId、sourceTagId（可空审计关联）、snapshotVersion、snapshotJson、createdAt、expiresAt；分享快照不因源标签删除而被外键级联清除，其有效性独立按 expiresAt 判断。快照不包含账号资料、公共图标、订单或私人比赛备注；不依赖原成员 ID 或本库 groupId 才能导入，使用成员原名与当前别称规则解析，不改写公共别称。

随机码应由 Web Crypto 生成足够随机字节（建议至少 128 位随机性）再编码为易复制字符串；数据库仅存码的哈希，不记录明文到日志。现有 db/schema.ts 的 account_sessions 已使用 tokenHash/expiresAt，可参考其职责边界，但分享码不得复用登录 token 或会话表。接口均需登录，创建只允许分享自己的标签；导入凭有效码授权读取该份快照并复制，不获得源账号其他标签或后续修改权限；private/no-store，不提供公开配置查询。限制码长度、创建/猜码请求频率与快照体积，返回清晰的失效/过期提示。

已确认有效期 24 小时，期限内允许多个账号使用，不因首次使用而失效。前端显示北京时间失效时间。服务端每次导入实时判断过期，不能依赖清理任务；过期清理可延迟执行，不是本次额外新增定时任务的前提。有效性检查应与落库在同一事务/条件写入边界内，避免到期竞态导致半份导入。

导入必须限制成员数量、文本长度、颜色和日期格式，并重新按最新别称去重；若快照中的 a/b 已汇合为同队，遵循「配置时重复应中断」规则，整份拒绝并指出冲突，不自动覆盖或丢弃备注。可由分享者先整理标签后重新生成分享码，不额外引入前端改写后绕过码导入的路径。导入记录与全部成员必须整批成功或失败。

同一次 requestId 重试返回同一结果；是否对同账号同分享码的另一次主动导入也去重可在 Planning 明确，建议提示已导入并返回已有副本，避免无意复制。不同有效分享码分享同名标签时仍不自动覆盖现有配置。本次不改动原 JSON v5「设置/完整数据」交换格式。

## 交互建议

- 设置页每个标签展示全名、短文案预览、底色、日期和成员数；成员列表可搜所有别称，每行编辑本标签下该队备注。已有 ColorPicker 与 readableTagTextColor 可复用，按背景自动选可读字色。
- 保留主客队现有顺序：主队「(别称) [标签] 主名」，客队「主名 [标签] (别称)」。只有主名时建议标签放主名旁边，避免有队伍配置却因没有别称而不展示。
- 支持多个有效标签并按配置顺序排列；固定露出前 3 个，其余 +N，N 为有效标签总数减 3（按标签计数，不按合并来源成员计数）。+N 的 hover/focus 浮层展示全部有效标签及备注，手机点按可查看。无效/过期标签不计入数量；不因窄屏静默减少至 1～2 个，布局需为 3 个加 +N 验证。
- 短文案建议限制 1～2 个可见字符；未填时取 trim 后标签全名的首个可见字符，正确处理 emoji，不能直接使用 string[0]。例如「26 欧冠」默认是「2」，希望显示「欧」可显式配置。
- 标签浮层主行显示全名，字号稍大且加粗；下面按备注来源分块换行，多行备注保留内部换行，不限定两行。每份备注末尾提供编辑 icon，点击仅该备注切换输入框，建议使用支持多行的 Input.TextArea；显式保存/取消，不点击 tag 就直接进入编辑。
- 因浮层含可操作 icon，应使用可交互 Popover 实现 tooltip 外观；hover 后鼠标移入浮层保持打开，进入编辑后固定浮层，避免移出即丢草稿。+N 内各标签采用相同备注编辑方式，重复露出的标签也指向同一 memberId。
- 手机点击 tag/+N 打开浮层，键盘 focus/按键也可操作。失败保留草稿，保存中禁用重复提交，409 保留草稿并提供加载最新；编辑时不因背景刷新重置。长内容换行并限制浮层高度可滚动，不把编辑按钮截断；内部事件不触发卡片其他操作。

## 实现阶段验证范围

- 匹配：主名、别称、未激活名、标准化名称均命中同组；未知组原名精确匹配；改名/组删除/移组回退；单主名、多标签、主客顺序及查询高亮不受影响。
- 去重与合并：已知 a/b 同队时新增拒绝；先添加后合并时同标签只显示一个 tag、备注按来源多行保留；单行编辑不改其他备注，别称拆开可恢复各自归属；旧合并数据仍可编辑元数据和备注；跨标签互不影响；公共别称变化与添加同时发生的竞态。
- 分享导入：创建接口仅可分享本人标签；中文/emoji/多行与备注完整往返、快照固定、独立归属与新 ID；非法码、过期边界、未知快照版本、大小限制、当前别称重复、整批失败回滚；同请求重试幂等、多人使用、导入后重载成功与失败，不能改写公共别称或泄露其他标签。
- 日期/文本：长期、单端范围、双端边界、跨年、北京时间零点、非法日期、倒序；默认首字符、emoji、空文案、颜色校验及字色对比。
- API/D1：增删改、成员重复/不存在、整批成功与失败回滚、401、伪造他人 tagId/memberId/userId 的越权拒绝、revision 冲突、并发编辑与首次写入；账号隔离、退出清理和旧请求不串账号；普通登录用户可管理自己标签。
- 状态：读取失败可重试、保存成功同队多卡同步、失败保留草稿、旧 GET 不覆盖新保存、删除/过期不误删比赛与订单。
- 浏览器桌面与移动端：0/1/3/4/多个标签、+N 显示全部标签和备注、移入浮层保持打开、备注末尾 icon 与单独编辑、合并多行、名称截断仍能看到标签、点按/键盘、滚动、错误与窄屏；独立 HTML 不泄露私人数据。
- 实现后按风险执行相关测试与 npm test、npm run lint、npm run build。本轮仅阅读及新增 Research 文档，未运行功能验证。
