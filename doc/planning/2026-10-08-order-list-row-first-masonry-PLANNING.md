# 订单瀑布流横向优先排序 Planning

关联 Research：`doc/planning/2026-10-08-order-list-row-first-masonry-RESEARCH.md`

## 实施方案

1. 每个订单批次保留原始索引，并按偶数/奇数索引拆分为左右两列。
2. 将 `.orders-grid` 从 CSS 多栏改为两列 grid，新增纵向 `.orders-grid-column`，继续保持不同高度卡片的瀑布流堆叠。
3. 720px 以下把列容器展平为单列 flex，并使用卡片原始索引恢复自然顺序。
4. 验证桌面端横向优先分配、加载更多后旧批次稳定，以及移动端顺序与横向溢出。

## 接口与兼容

- 不修改 API、D1、订单结构、查询分页或持久化顺序，不需要迁移或历史数据处理。
- 继续按 `savedAt` 降序展示，并继续使用每 10 单一个稳定批次。
- 卡片只渲染一次，现有展开、编辑、支付、结账和删除状态保持原组件实例与 key。

## 发布影响

- 这是订单列表布局行为调整，正式发布时按 `minor` 更新版本。
