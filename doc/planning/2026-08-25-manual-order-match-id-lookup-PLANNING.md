# 手动订单按 matchId 查询比赛与自定义创建时间 Planning

## 已确认决策

- 接受元数据降级策略：先查 fixed bonus；本地没有完整元数据时查询官方当前比赛列表；仍无法补齐则提示手填，不伪造日期、时间或场次号。
- 临时比赛使用按标准化 `matchId` 索引的字典，支持一个手动订单查询多场比赛。
- 大于 5 位纯数字按至少 6 位处理，并同步放宽 textarea 解析与保存校验。
- 手动订单创建时间可留空，留空时使用提交瞬间的当前时间。

## 接口与数据结构

- 不新增项目 API 或数据库迁移，复用前端已有的体彩官方请求方法。
- 新增查询方法输入标准化 `matchId`、当前本地比赛和可选当前时间，返回完整 `MatchItem | null`。
- fixed bonus 负责队伍、联赛、五类玩法赔率、赔率历史、让球数和单关信息；本地比赛或当前比赛列表负责日期、开赛时间、周几和场次号。
- 临时比赛只存在于手动订单弹窗组件状态，不写入公共 `matches`、浏览器比赛缓存或云端比赛表。
- 订单 `savedAt` 继续使用 ISO 字符串，不改变 API、D1 或导入导出结构。

## 兼容与错误处理

- 非纯数字、不足 6 位、已存在临时结果的搜索不重复请求。
- 搜索请求防抖；每个 entry 保存最新查询 ID，忽略旧查询和弹窗关闭后的响应。
- fixed bonus 请求失败、响应 ID 不一致或没有有效赔率时提示查询失败。
- fixed bonus 成功但无法补齐基础元数据时提示继续手填，不加入临时下拉选项。
- 历史 6 位和当前 7 位 matchId 都可写入文本和订单；重复比赛检查仍使用标准化 ID。
- 自定义创建时间不限制过去或未来，与现有订单编辑器保持一致；其订单筛选、排序和趋势影响沿用现有 `savedAt` 语义。
