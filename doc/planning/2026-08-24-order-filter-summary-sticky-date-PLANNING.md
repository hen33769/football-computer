# 订单筛选汇总与投注日期吸附 Planning

日期：2026-08-24

关联 Research：`doc/planning/2026-08-24-order-filter-summary-sticky-date-RESEARCH.md`

## 目标

- 在订单筛选汇总中同时展示全部筛选订单的投入总额和其中已经支付的金额。
- 保持筛选盈亏沿用“已支付支出 - 已结账收入”的账本口径。
- 让投注页日期折叠标题吸附在收起后的固定页头下方，并以页面背景色遮挡滚动内容。

## 实施方案

1. 在 `app/imports.ts` 增加全部订单投入汇总函数，逐单复用 `calculateStake`；保留 `orderLedgerTotals` 的已支付支出语义。
2. 在 `app/FootballApp.tsx` 为当前筛选结果分别计算总投入、已支付支出、收入和盈亏。
3. 将汇总顺序调整为“筛选结果 / 筛选总额 / 已支付 / 筛选盈亏 / 说明”，并同步修改盈亏 Tooltip 文案。
4. 将 `.order-filter-summary` 桌面网格扩为五列，保留窄屏两列布局及说明文字跨列规则。
5. 为 `.date-divider` 增加 `position: sticky`、固定页头后的 `top` 偏移、比赛卡片之上的层级和 `var(--canvas)` 不透明底色。
6. 增加金额口径单测，随后运行 diff 检查、测试、Lint、构建和桌面/手机浏览器验证。

## 兼容与发布影响

- 不改变订单数据结构、API 请求、D1 数据或支付/结账行为。
- 未支付历史订单仍只出现在“筛选总额”，不会进入累计支出或筛选盈亏。
- sticky 使用原生 CSS，不新增滚动事件或运行时状态。
- 实现完成后开发者已明确要求提交、推送和部署；本次按行为调整发布为 `v1.11.0`，并在同一发布提交中同步 `UPDATE.md`、`package.json` 与 `package-lock.json`。
- 部署目标为 `origin/main`、Cloudflare Worker `smgr-cloud` 和正式域名 `smgr.online`；由于没有数据库变更，本次不执行远端 D1 迁移或订单重写。

## 实施结果

- 新增 `orderStakeTotal`，当前筛选内所有订单都计入“筛选总额”；`orderLedgerTotals().expense` 继续只统计已支付订单，并以“已支付”展示。
- 筛选盈亏继续使用筛选收入减已支付金额，未支付订单不会提前形成亏损。
- 订单汇总顺序已调整为“筛选结果 / 筛选总额 / 已支付 / 筛选盈亏 / 说明”，桌面使用五列，手机使用两列。
