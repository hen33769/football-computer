# 比赛卡片比分居中对齐 Planning

日期：2026-08-20

关联 Research：`doc/planning/2026-08-20-match-score-alignment-RESEARCH.md`

## 目标

- 比赛卡片中央基准从“整段文字内容宽度”改为固定的比分分隔符中轴。
- 主行使用对称五列布局，副行使用与主行中央轨道同轴的三列布局。
- 有无比分、队名长短、桌面双列、平板单列和手机窄屏下，`:` 或 `VS` 都严格位于卡片内容区中心。
- 全场比分按主胜红、平局蓝、主负绿着色；半场比分按自身胜平负着色并使用约 55% 透明度。
- 不改变比赛数据、自动赛果获取、投注选择、赔率区或订单逻辑。

## 已确认设计

### 主行五列

从左到右固定为：

1. 主队名称
2. 主队全场进球
3. 全场分隔符 `:`，无比分时显示 `VS`
4. 客队全场进球
5. 客队名称

初始列比例为 `5 : 1 : 0.5 : 1 : 5`。第一、二列右对齐，第三列居中，第四、五列左对齐。队名轨道等宽，超出时保持当前单行省略行为。

### 副行三列

- 主队半场进球、`:`、客队半场进球分别占用主行第二、第三、第四列。
- 副行分隔符与主行分隔符共享同一水平中轴。
- 没有半场比分时不渲染副行，不创建空白高度。

### 无比分

- 主客队仍位于第一、第五列。
- 第二、第四列不显示内容。
- 第三列显示现有 `VS` 文案并使用中性灰色。

### 颜色

- 全场主胜：`#d8424c`。
- 全场平局：`#1673bd`。
- 全场主负：`#218a73`。
- 半场使用自身比分独立判断胜、平、负，复用对应颜色并设置约 `55%` 透明度。
- 颜色只应用于进球数字和 `:`；队名继续沿用正常/已停售颜色。
- 当前已停售选择器会把全场比分覆盖为灰色，实施时必须移除该比分覆盖或让赛果 class 具有明确更高优先级，同时保留已停售队名为灰色。

## 实施方案

### 1. 调整 `MatchCard` 的派生状态

文件：`app/FootballApp.tsx`

- 在组件渲染前分别根据 `fullScore.home/away` 和 `halfScore.home/away` 计算全场、半场赛果 tone。
- tone 使用三个稳定值，例如 `home`、`draw`、`away`；全场与半场必须独立计算，不能让半场复用全场结果。
- 无对应比分时不生成 tone，确保 `VS` 保持中性样式。
- 计算仅服务于展示 class，不修改 `match.result` 或任何持久化数据。

### 2. 将主、副行改为可定位节点

文件：`app/FootballApp.tsx`

- 不再把完整全场比分拼成一个字符串节点；将主队进球、分隔符和客队进球拆为独立节点。
- 主队名、三个比分节点、客队名按 DOM 顺序组成主行五块，并增加职责明确的 class。
- 半场比分由三个独立的浅色节点组成，分别定位到中央三列的第二行。
- 无全场比分时只渲染中央 `VS`；Grid 的第二、第四列自然留空，不用插入可见占位字符。
- 保持文本顺序可读：主队名称 → 主队进球 → 分隔符 → 客队进球 → 客队名称 → 半场比分。

### 3. 使用单个共享 Grid 建立中轴

文件：`app/globals.css`

- 从 `.match-meta, .teams-row, .market-name-line` 的共享 flex 规则中移出 `.teams-row`，避免 flex 与 grid 冲突。
- 将 `.teams-row` 改为五列、两行 Grid，列模板初始使用 `5fr 1fr .5fr 1fr 5fr`，宽度占满卡片内容区。
- 主行所有节点位于第一行；半场三个节点位于第二行的第 2～4 列。
- 主队名和主队进球使用右对齐，客队进球和客队名使用左对齐；分隔符使用自身居中。
- 给所有队名节点设置 `min-width: 0`、单行省略和正确的 text alignment，保证长队名向外侧占用空间而不挤压中央比分。
- 保留当前主行/副行字号、行距和卡片上下间距，避免比分对齐修复引起卡片高度变化。

### 4. 增加赛果颜色并处理停售覆盖

文件：`app/globals.css`

- 为全场比分的 `home/draw/away` tone 增加项目现有红、蓝、绿颜色。
- 为半场比分复用相同 tone 颜色，并通过统一 opacity 约 `0.55` 形成浅色层级。
- 调整 `.match-card.stopped` 相关选择器：已停售仍使队名和时间变灰，但不得覆盖带赛果 tone 的全场或半场比分。
- `VS` 使用现有灰色，不能继承任何上一次赛果或 tone。
- 保留 `font-variant-numeric: tabular-nums`，避免数字宽度变化。

### 5. 响应式与视觉微调

文件：`app/globals.css`

- 在双列卡片宽度下先验证 `5 : 1 : 0.5 : 1 : 5`；只有出现队名过早截断或比分间距明显松散时才做对称微调。
- `1180px` 以下单列布局继续复用同一比例，不根据内容切换另一套对齐逻辑。
- `560px` 以下保持现有 14px 队名字号，并检查中文、英文和中英文混合长队名。
- 任何微调都必须保持左右镜像，不能为某一侧单独增加宽度或 margin。

## 验证计划

### 静态检查

- 运行 `git diff --check`。
- 运行 `npm test`，确认赛果、比赛和投注计算未受展示改动影响。
- 运行 `npm run lint`。
- 运行 `npm run build`。

### 浏览器验证

- 桌面双列：验证主队长/客队短、主队短/客队长、两边等长三类卡片。
- 单列与手机：分别验证 `1180px` 以下和 `560px` 以下布局。
- 状态覆盖：无比分、仅全场比分、全场及半场比分。
- 颜色覆盖：主胜、平局、主负各至少一场；再验证半场结果与全场结果不一致的比赛，确认两行可使用不同语义色。
- 几何测量：比较 `.teams-row` 内容区中心、全场分隔符中心和半场分隔符中心，横向误差不超过 1px。
- 截图复核：队名长度差异只影响各自外侧内容，不能推动比分中轴；长队名超出后显示省略号且比分不换行。
- 检查浏览器控制台，不能新增 React key、DOM 嵌套或样式相关错误。

## 风险与控制

- 风险：共享选择器中的旧 flex 属性继续作用于 `.teams-row`。控制：实施时先拆共享规则，再定义 Grid，并用计算样式确认 `display: grid`。
- 风险：已停售高优先级规则把语义色重新覆盖成灰色。控制：使用比分节点专属 tone 选择器，并逐一验证三种赛果颜色。
- 风险：半场错误复用全场 tone。控制：组件内分别计算两个 tone，并选取上下半场结果不同的真实样例验证。
- 风险：Grid 比例在窄屏使英文队名过早省略。控制：保持对称前提下视觉微调，并覆盖 560px 以下测试。
- 风险：为了占位插入空文本导致辅助技术或复制文本出现多余内容。控制：依靠未占用 Grid 轨道留空，不插入可见占位字符。

## 实施结果

- `MatchCard` 已分别计算全场和半场 tone，并将比分拆成可独立定位、着色的节点。
- `.teams-row` 已使用 `5fr 1fr .5fr 1fr 5fr` Grid；主行五块与副行中央三块共享同一中轴。
- 无比分继续显示居中的 `VS`，已停售只影响队名和时间，不再覆盖赛果颜色。
- 全场复用项目红、蓝、绿语义色；半场按自身比分计算颜色并设置 `opacity: .55`。
