# 手动添加订单比赛选项排序 Research

## 需求边界

- 手动添加订单的比赛下拉选项按订单录入习惯排序：比赛日期降序，同日按周次和场次号升序，例如“周一 001、周一 002”。
- 保留比赛 ID 查询、临时比赛数据合并、重复比赛禁用和本地搜索行为。

## 现有实现

- `app/FootballApp.tsx` 的 `manualMatchOptions` 使用 `sortMatchesForManualOrder(manualMatchSources)` 生成下拉选项。
- `app/sorting.ts` 当前比较顺序为：日期降序 -> 开赛时间升序 -> 文本时间 -> 场次号 -> 比赛 ID。
- 因此同一天会优先按开赛时间排列；若场次号与开赛时间顺序不同，就会出现截图中的 `008、007、009、011、010...`。
- 现有测试只覆盖了开赛时间顺序与场次号顺序一致的样例，无法捕捉本次问题。

## 约束与风险

- 比赛日期必须保持第一排序键，不能按时间戳跨日期重新排序。
- 同日应以周次、场次号为主要顺序；场次号需要使用自然数字比较，保证 `001、002、010` 的顺序。
- 对缺少或异常元数据的手动查询比赛保留稳定的 ID 兜底排序。

## 修复方向

- 将 `compareManualOrderMatches` 调整为：日期降序 -> 周次自然排序 -> 场次号自然排序 -> 比赛 ID。
- 删除开赛时间作为同日主排序键，新增一个开赛时间与场次号相反的回归样例。

## 待验证

- 同日场次号始终按 `001、002、003...010` 排列，不受开赛时间影响。
- 不同日期仍按新日期在前排列。
- 手动添加页面下拉列表可加载，桌面端和移动端无控制台错误。
