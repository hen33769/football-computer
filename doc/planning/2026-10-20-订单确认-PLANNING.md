  - `BulkOrderOperation` 增加 `confirm`，订单进度增加 `unconfirmed`。

- [x] 2. 新增 D1 迁移
  - 新增 `0012_order_confirmation.sql`，为 `user_orders` 增加可空 `confirmed_at`。
  - 更新 Drizzle schema、SQLite 测试辅助迁移和所有订单读写 SQL。
  - 历史订单不回填确认时间。

- [x] 3. 实现服务端确认与筛选
  - `confirm` 操作只接受已结账、成功且未确认订单，由服务端生成确认时间。
  - 普通更新拒绝客户端新增或篡改确认时间；已确认订单税额变化时清除确认。
  - 撤回结账与再次判断赛果清除确认。
  - `unconfirmed` 查询使用 `settled_at IS NOT NULL AND status = 'success' AND confirmed_at IS NULL`。

- [x] 4. 更新页面交互
  - 游客与云端订单确认都复用现有订单 mutation 流程。
  - 确认按钮放在撤回按钮左侧；确认后展示不可重复操作的“已确认”状态。
  - 订单进度增加“未确认”，游客本地筛选与云端查询使用相同条件。

- [x] 5. 验证与文档收尾
  - 增加模型、筛选、确认权限/并发/事务和生命周期测试。
  - 运行 `npm test`、`npm run lint`、`npm run build`、本地 D1 迁移。
  - 验证桌面端与移动端按钮位置、确认状态和未确认筛选，并记录结果。

## 接口与兼容性

- 订单请求与响应新增可选 `confirmedAt`。
- `/api/orders/bulk` 新增 `operation: "confirm"`，现有接口路径不变。
- `/api/orders?progress=unconfirmed` 返回已结账、成功、未确认订单。
- 旧客户端不发送该字段仍可工作；历史订单因 `confirmed_at` 为空而保持未确认。

## 发布影响

- 新增 D1 迁移并增加订单确认能力，和本轮税额功能一并按 minor 版本发布。
- 本次只实现和本地验证，不提交、推送、远端迁移或部署。
