# 赛事前瞻非友谊赛筛选 Planning

日期：2026-08-25

关联 Research：`doc/planning/2026-08-25-preview-non-friendly-filter-RESEARCH.md`

## 目标

- 在赛事前瞻的两组“同赛事”左侧增加默认选中的“非友谊赛”。
- 在前端精确排除 `tournamentShortName` 为 `俱乐部赛` 的历史交锋和比赛近况列表项。
- 保持现有官方接口参数、汇总统计和其它前瞻模块不变。

## 实施方案

1. 在 `app/sporttery-insights.ts` 增加纯函数，根据开关状态返回原数组或排除 `俱乐部赛` 后的新数组。
2. 扩展 `PreviewFilters`，在“同赛事”前渲染“非友谊赛”，复用现有选中态、loading、点击和键盘交互。
3. 为历史交锋和比赛近况分别增加默认值为 `1` 的前端筛选状态；该状态不进入请求 key 和请求参数。
4. 历史交锋过滤 `history.matchList`；比赛近况分别过滤 `recent.home.matchList` 与 `recent.away.matchList`。
5. 增加纯函数测试，随后运行 diff 检查、测试、Lint、生产构建和桌面/移动端浏览器验证。

## 接口、兼容与发布影响

- 不修改 `tournamentFlag`、`homeAwayFlag` 或任何官方接口 URL。
- 不修改前瞻响应结构、比赛模型、D1 或持久化数据。
- 开关关闭时直接恢复原始列表；已有“同赛事”和“同主客”行为保持兼容。
- 本次属于前瞻筛选行为调整；用户尚未要求提交、推送或部署，因此暂不调整版本号和 `UPDATE.md`。

- 新增 `filterNonFriendlyTournamentRows`，开启时精确排除去除首尾空格后为 `俱乐部赛` 的列表项，关闭时直接返回原数组。
- `PreviewFilters` 的标签顺序调整为“非友谊赛 / 同赛事 / 同主客”，沿用原有 Tag 选中、loading、点击和键盘交互。
- 历史交锋和比赛近况分别持有默认值为 `1` 的独立开关；历史交锋过滤一份列表，比赛近况同时过滤主队和客队列表。
- 新开关没有进入 request key 或官方接口参数，切换时只做前端渲染；接口汇总统计继续使用官方原始口径。
