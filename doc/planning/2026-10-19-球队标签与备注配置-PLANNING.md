# 球队标签与备注配置 Planning

日期：2026-10-19。依据同日 [Research](./2026-10-19-球队标签与备注配置-RESEARCH.md) 及用户确认；2026-10-20 按实现结果同步维护 TODO 与接口细节。

## 目标与已确认范围

登录用户可在设置页维护自己的球队标签，包含名称、底色、1～2 个可见字符的短文案、日期范围、日期参照和球队成员备注。短文案留空取标签名称首个可见字符；日期参照默认「当前日期」，可改「比赛日期」；范围可空，使用北京时间自然日且包含两端。

投注赛事卡片通过队名及公共别称匹配标签，显示所有生效标签，前 3 个直接显示，其余 +N；+N 浮层显示该队全部有效标签和备注。标签放在主名与别称之间，没有别称时放主名旁。浮层标签全名加大加粗，备注按来源换行，各备注末尾编辑按钮只编辑该份备注。

配置时拒绝同标签内已知同队的重复成员；后续别称变更造成历史成员合并时只合并展示，备注原记录保留、可分别编辑。跨标签互不影响。

单标签分享调用后端生成 24 小时有效的分享码，期限内多个账号均可导入。分享为生成时完整快照，含备注；导入为当前账号独立副本，成功后重新加载个人标签。游客/独立 HTML 不提供个人标签存储，本次不改变通用 JSON v5 备份格式。

## 数据结构与迁移

新增 `drizzle/0008_user_team_tags.sql`、`0009_team_tag_import_rate_limits.sql` 与 `0010_team_tag_mutation_tokens.sql`，同步 `db/schema.ts`；不修改 0000～0007。0010 的一次性写入标记用于把父标签条件更新与后续成员写入绑定为同一操作，旧 revision 请求不能借用并发请求的新 revision。

| 表 | 核心字段与约束 |
| --- | --- |
| `user_team_tags` | id 主键、user_id 外键、name、short_text、color、date_basis、start_date/end_date 可空、display_order、revision、created_at/updated_at。user_id 删除级联；索引 user_id/display_order；date_basis 限 current/match。 |
| `user_team_tag_members` | id 主键、tag_id 外键、source_name、source_name_key、team_group_id 可空、note、display_order、revision、updated_at。标签删除级联；唯一 tag_id/source_name_key。team_group_id 为关联提示，不设公共组删除级联，不丢私人记录。 |
| `team_tag_shares` | id 主键、code_hash 唯一、owner_id 外键、source_tag_id（审计值，不级联源标签）、snapshot_version、snapshot_json、created_at/expires_at。索引 owner_id/created_at、expires_at；账号删除级联。 |
| `user_team_tag_imports` | user_id + share_id 唯一、独立 import id、target_tag_id、request_id、created_at；另唯一 user_id/request_id，用于防止重试重复创建。保存导入回执，不存明文分享码。 |
| `team_tag_import_rate_limits` | user_id + 分钟窗口为主键，原子累计导入尝试；每账号每分钟最多 20 次，账号删除级联。 |

约定：删除已导入的副本后，显式再次导入可创建新副本并更新回执；副本仍存在则同账号同码返回已有副本。不同码即使同名也创建独立标签，不覆盖。有效分享码不因源标签编辑/删除而变化；删除账号后相关分享失效。过期快照可后续清理，本次不新增定时任务；回执不依赖过期清理才能保证幂等。

新增 `app/team-tags.ts`：DTO、草稿、成员解析、标签有效性、短文案回退、展示分组与校验工具。拟定限制：标签名称 80 个可见字符、短文案 2 个、队名沿用 80 字符、单份备注 2000 字符、每标签 200 个成员、每账号 200 个标签、分享快照不超过 1 MiB。上述为实现限制，前后端同源；空白 trim，内部备注换行保留，纯文本渲染。颜色只接受不透明 #RRGGBB。

## 身份解析与重复处理

1. 复用 normalizeTeamName；sourceName 当前命中公共别称组时使用该组 ID；否则回退仍存在的 teamGroupId；再否则使用标准化原名。赛事名称也通过同一索引解析，支持未知队伍精确匹配，不做模糊归队。
2. 输入支持搜索现有组或直接输入名称。成员保存原始名称和独立 ID；不能只存名称行 ID，也不能用列表位置作身份。新成员的 group 提示由服务端根据当前索引生成。
3. 同标签新增成员时比较其当前身份与全部现有成员；新输入之间也比较。发现冲突整体拒绝新增并列出原名及当前主名；已有历史合并成员可继续改备注/标签元信息，不作为阻断条件。
4. 展示按 tagId + 当前身份聚合，一个 tag 下保留有序 memberId/note/sourceName 列表。相同内容不自动去重，空备注仍有编辑入口；来源队名轻量显示。别称分离后按原记录恢复展示，不写破坏性合并迁移。
5. 结构写入与别称判断不能仅采用事务外 SELECT 后无条件写。采用 D1 batch 内条件写：最终添加 SQL 通过当前 shared_team_names/group 关联重新计算身份，并在 INSERT 的 NOT EXISTS 条件中校验重复；新建/导入的父标签插入同时检查全部候选成员两两重复。后续成员 INSERT 依赖父标签成功存在，父插入 0 行则所有后续写入无效，返回 409。多成员添加及结构修改使用同一 batch，并通过 revision 条件控制；不可先写部分成员再在 JS 抛错冒充回滚。
6. 实现 SQL 复杂度优先服务正确性；必须用真实 SQLite 验证原子条件和失败路径。D1 batch 不使用交互式 BEGIN，也不假定普通 JS 回调拥有事务。SQL 约束异常整批回滚；业务前置条件不满足时整批不写。公共别称事务在本批之前提交则按新关系校验，在之后提交则视为合法的后续合并。

## 私有 API 与并发

新增 `app/server/team-tags-service.ts`、`app/api-client/team-tags.ts` 与私有路由。复用 requireAuthenticatedCloudAccount、routeError、requestJson；所有响应含错误为 private/no-store，所有写入验证当前账号归属与字段白名单。

| 接口 | 行为 |
| --- | --- |
| GET `/api/users/me/team-tags` | 读取本人标签及成员，稳定按 display_order/id 排序；含 revision，不返回分享密钥。 |
| POST `/api/users/me/team-tags` | 创建标签及初始成员，整批校验/写入，返回完整新标签。 |
| PATCH `/api/users/me/team-tags/[tagId]` | 原子更新标签元信息和成员结构，必须 expectedRevision；历史别称合并成员仅在原成员名称未被改写时允许继续保存。 |
| DELETE `/api/users/me/team-tags/[tagId]` | expectedRevision，删除标签及成员，处理未完成编辑冲突，不操作公共配置。 |
| PATCH `/api/users/me/team-tags/[tagId]/members/[memberId]` | `{note, expectedRevision}`，仅修改该成员备注；原子 revision 条件 UPDATE。 |
| POST `/api/users/me/team-tags/[tagId]/shares` | expectedRevision；读取本人已保存完整快照，产生随机码，返回 code/expiresAt。 |
| POST `/api/users/me/team-tags/import` | `{code, requestId}`；查哈希、判断期限、验证快照及重复成员，事务创建副本/回执；已有有效回执返回原结果。 |

接口名可随现有路由约定微调，但数据边界不变。非法字段/日期/码格式 400，未登录 401，非本人资源按 404 处理，版本/别称重复/到期竞态 409，码不存在或已过期返回统一可理解的失效提示，触发配额 429。

备注版本独立；成员变化及备注变化同时递增所属标签 revision，使标签删除、结构编辑、分享 expectedRevision 能识别快照已变。所有条件写成功与否在 SQL 内相互约束，不能父版本失败而子记录仍写入。前端保存后使用返回的最新成员与标签版本；409 保留草稿，允许重新加载，不静默覆盖。

## 分享实现

使用 Web Crypto 至少 128 位随机字节，编码成可复制字符串；服务端 SHA-256 后查库存储，明文仅创建时返回，不输出到日志。快照版本固定为 1，包含全部配置与原始成员备注，不包含原账号和内部成员身份；原组提示不作为导入可信身份。

创建时以一致的标签版本取得快照并条件 INSERT；版本变化则提示重试。expiresAt = 后端生成时刻 + 24 小时，判断 `now < expiresAt` 才有效，前端显示北京时间失效时间。导入的父标签条件 INSERT 同时检查未到期与无身份重复，后续成员和回执依赖该次父写入结果，均在同一 D1 batch。分享码支持多人，不标记一次性 consumed。

同账号 requestId 原子唯一防并发重试；并发同码另请求也通过 user_id/share_id 唯一回执及事务回滚避免重复副本，冲突后读取已有结果。已成功请求重试优先查本人回执，即使此刻码已到期也可返回之前成功的结果，但不能因此新建副本。创建建议每账号每小时至多 30 次，导入尝试每账号每分钟至多 20 次；实现时使用跨请求共享的 D1 条件计数或已有可靠限流设施，不能仅进程内计数。采用 D1 时新增对应窗口计数表及索引，随新增迁移一并维护。

## 页面与状态

新增 `TeamTagSettings`、`TeamTagBadges`、`TeamTagPopover` 及必要子组件，将本功能逻辑从 FootballApp 拆出，保持主页面负责传参。复用 ColorPicker/readableTagTextColor、Ant Design Popover/Input/DatePicker 与现有通知样式，不复制个人比赛备注的数据服务。

- 设置页：个人「球队标签配置」与管理员「队伍信息配置」为两个独立卡片，各自折叠；点击各自新增按钮时自动展开。标签支持列表/新建/编辑/删除/导入；每个标签含分享按钮、预览、日期模式/范围、队伍联想输入及来源备注。联想候选来自独立的队伍信息配置并支持别称搜索，也允许直接加入手填名称；新增放顶部，现有编辑保持位置，暂不新增拖拽排序。
- 分享：有未保存内容先保存；点击调用接口，成功展示码、复制按钮、失效时间和「包含球队备注」提示。剪贴板失败仍可选中文字复制。
- 导入：输入码后显式点击导入，后端直接保存；不增加必须的预览接口。失败保留输入，成功重新加载个人列表，重载失败只重试 GET。别称重复时返回具体冲突，分享者整理后重新分享。
- 比赛卡片：TeamNameWithAlias 增加可选插槽，仅 MatchCard 传入标签，不全局扩散；保留主队「别称→标签→主名」、客队「主名→标签→别称」，无别称放主名邻侧。固定保留 3 个标签和 +N 占位，优先截断名字；不遮盖比分与图标。
- 浮层：hover/focus 展示，手机点击打开；+N 按标签分区显示全部。每份备注尾部编辑 icon，编辑后为多行输入框加保存/取消；编辑期间固定浮层，其他备注不重置。保存失败保留输入、错误可读，409 可加载最新；浮层可滚动、窄屏不溢出，键盘可操作，内部点击不触发卡片其他事件。
- 数据：登录 bootstrap 加载个人标签，不因该请求失败阻断订单或比赛；状态区分 loading/error/empty。失败可重试，未加载成功不允许盲写。公共别称加载失败时暂停新增/导入，服务端仍独立校验。进入标签设置、手动刷新及成员提交后同步别称；备注保存同步同队各卡片。
- 生命周期：独立按账号管理状态，不持久化到公共缓存；退出/切换账号清草稿并忽略旧异步响应，按版本合并响应。用现有 now 驱动当前日期模式跨零点计算，比赛日期取开赛时间而非业务日。
