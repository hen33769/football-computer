# 手动订单时间与比赛聚焦 Research

- `app/FootballApp.tsx` 的 `manualOrderSavedAt` 只存 React 状态；打开和成功关闭弹窗都不清空，符合旧计划的同组件生命周期保留，但组件重新挂载或页面刷新会丢失。当前仅查看代码无法确定用户此次具体触发了何种丢失。
- 用户留空时 `persistNewOrder` 在提交时生成时间，表单本身不会被回填；已填写则转换为 ISO 并写入订单 `savedAt`。已有订单不会因表单状态变化而修改。
- 已有 `sessionCache` 支持页面会话持久化并在存储不可用时回退内存；`FootballRoute` 按账号 ID 重新挂载应用，应隔离不同账号的时间，避免互相继承。仅保留显式选择的时间，清空仍表示每次使用提交时当前时间。
- `addManualOrderEntry` 已优先查找第一个文本为空的条目；没有空条目时添加新条目。`scrollManualOrderPickerIntoView` 仅滚动列表而不聚焦 Select，新增条目通过 layout effect 等待渲染。
- 保持 8 场上限、已填文本判断和滚动行为；使用 Ant Design Select 的公开 focus API，处理已存在空项和刚创建项并关注移动端软键盘、弹窗生命周期。
