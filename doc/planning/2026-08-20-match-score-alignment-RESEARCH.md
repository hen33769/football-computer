# 比赛卡片比分居中对齐 Research

日期：2026-08-20

## 需求理解

- 比赛卡片不应再把“主队名称 + 比分/VS + 客队名称”作为一个整体居中；比分分隔符应始终落在卡片内容区的水平中轴。
- 主行拆成五个对称区域：主队名称、主队进球、分隔符、客队进球、客队名称。
- 主队名称和主队进球向右对齐；客队进球和客队名称向左对齐；有比分时使用英文半角 `:`，并让它严格居中。
- 没有比分时也沿用同一套对称布局，避免队名长度影响中央 `VS` 的位置。
- 半场比分副行拆成三个区域：主队半场进球、`:`、客队半场进球；中间 `:` 与主行中轴一致。
- 继续保持主行全场比分较醒目、副行半场比分浅色显示的现有视觉层级。
- 主行全场比分增加赛果语义色：主胜红、平局蓝、主负绿；只改变比分数字与分隔符，不改变队名颜色。
- 副行使用对应的浅红、浅蓝、浅绿，或通过半透明复用主行语义色。

## 截图现象

- 截图中“凯尔特人 3 : 0 LASK林茨”“奈梅亨 1 : 3 博德闪耀”等队名长度差异明显的卡片，主行比分随整段内容偏移。
- 半场比分是独立元素，其自身被居中，因此主行和副行的冒号不在同一条竖直中线上。
- 无比分卡片当前显示“主队 VS 客队”，同样按三段内容的总宽度居中；只要两侧队名宽度不同，`VS` 就不会处于卡片中轴。

## 当前实现

### 组件

位置：`app/FootballApp.tsx` 的 `MatchCard`。

- `fullScore` 来自 `match.result?.fullScore`，`halfScore` 来自 `match.result?.halfScore`。
- 主行 DOM 当前只有三个子项：主队 `<b>`、包含完整 `主队进球 : 客队进球` 或 `VS` 的单个 `<span>`、客队 `<b>`。
- 半场比分是主行外的独立 `<small>`，内部是连续文本 `主队进球 : 客队进球`。
- 由于主客队进球和分隔符没有独立 DOM 节点，现有结构无法给五块主行和三块副行分别分配网格轨道。

### 样式

位置：`app/globals.css` 中 `.teams-row`、`.teams`、`.match-final-score` 和 `.match-half-score`。

- `.teams` 使用 `display: flex; justify-content: center; gap: 10px`，所以居中对象是三个子项的总内容宽度。
- 两个队名只设置了单行省略，没有获得等宽且对称的左右空间；主客队名字宽度不同时，中间比分必然偏移。
- `.teams-row` 使用纵向 flex 并居中，半场比分元素按自身宽度独立居中，所以副行冒号位于卡片中轴，却不会跟随已经偏移的主行冒号。
- `.match-card.stopped .teams .match-final-score` 会把已停售比赛的全场比分强制覆盖成灰色；而自动赛果只会出现在已停售比赛中，因此新增语义色时必须调整这条覆盖规则，否则红、蓝、绿不会生效。
- `560px` 以下仅把队名字号从 16px 改为 14px，没有改变对齐模型，因此桌面双列、平板单列和手机布局都会出现同类问题。

## 根因

当前对齐基准是“全部文字的总宽度”，而不是“比分分隔符所在的固定中轴”。队名是变长内容，任何一侧宽度变化都会推动完整比分或 `VS`。主行和副行又采用两套互不共享列宽的居中方式，因此无法保证竖直对齐。

## 建议实现方向

### DOM 结构

- 将全场比分的主队进球、分隔符、客队进球拆成三个独立节点，与两侧队名共同组成五列。
- 将半场比分也拆成主队进球、分隔符、客队进球三个独立节点。
- 无全场比分时保留五列结构：两侧进球列为空，中央分隔符列显示 `VS`；这样有无比分都使用同一中轴。
- 队名继续单行显示并保留省略号；只有内容超过各自对称队名列时才截断。

### 布局模型

- 使用 CSS Grid 代替主行当前的内容宽度 flex 居中。
- 五列必须左右镜像，例如“队名 : 进球 : 分隔符 : 进球 : 队名”为 `5 : 1 : 0.5 : 1 : 5`；最终比例应根据实际卡片宽度做浏览器视觉校准。
- 第一、二列右对齐，第四、五列左对齐；第三列自身居中，从而保证 `:` 或 `VS` 永远在卡片中轴。
- 副行的三列复用主行中央三个轨道的宽度和中轴，不能再按自身文本宽度单独居中。
- 比分数字继续使用 tabular numbers，避免数字字形宽度变化造成局部跳动。

### 颜色语义

- 项目在赛事前瞻、历史比分和胜平负摘要中已有统一赛果色：主胜 `#d8424c`、平局 `#1673bd`、主负 `#218a73`，比赛卡片应复用这套颜色，不再新增一组近似色。
- 全场比分根据 `fullScore.home` 与 `fullScore.away` 的大小关系得到主胜、平局或主负 class，并把同一颜色应用于主队进球、`:`、客队进球三块。
- 无比分时中央 `VS` 继续使用当前中性灰色，不添加赛果 class。
- 副行建议复用同一组语义色并降低透明度，而不是维护三种额外浅色；这样颜色来源唯一，后续主题调整也更一致。
- 队名继续沿用比赛状态颜色。已停售时只有比分恢复为语义色，主客队名称仍保持现有灰色层级。

## 状态与兼容范围

- 有全场和半场比分：两行冒号严格同轴。
- 只有全场比分：主行五列正常，副行不渲染，保持当前行为。
- 没有全场比分：中央显示 `VS`，两侧队名使用对称外列，`VS` 不随队名宽度移动。
- 极长或中英文混合队名：优先向各自外侧占用等宽队名列，超出后单行省略，不挤压比分中轴。
- 已停售队名颜色、字号层级、卡片高度、赔率区和按钮区不需要改变；仅比分不再受已停售灰色覆盖。
- 这是纯前端展示结构与 CSS 调整，不涉及比赛数据、赛果接口、D1 或订单逻辑。

## 预计影响文件

- `app/FootballApp.tsx`：调整 `MatchCard` 的主行和半场比分节点结构。
- `app/globals.css`：用对称 Grid 替换现有 `.teams` flex 对齐，并增加五列/三列的对齐样式和窄屏适配。
- 暂无适合现有 Node 测试框架的像素布局单测；应通过构建检查和浏览器几何/截图验证覆盖。

## 验证重点

- 桌面双列卡片下，分别使用“主队长/客队短”“主队短/客队长”“两边等长”三类队名验证中央位置。
- 对有比分、有全场及半场比分、无比分三种状态分别测量主行分隔符中心、半场分隔符中心和卡片内容区中心，横向误差应不超过 1px。
- 分别用主胜、平局、主负样例验证全场比分为红、蓝、绿；副行颜色与确定后的半场着色口径一致且明显浅于主行。
- 在 `1180px` 以下单列布局和 `560px` 以下手机布局复验，确认长队名只在各自外列省略，比分区不被挤压或换行。
- 确认有比分时只显示英文半角 `:`，无比分时中央 `VS` 仍保持当前文案和视觉层级。

## 已确认

1. 五列初始比例采用 `5 : 1 : 0.5 : 1 : 5`，再按桌面和手机截图微调。
2. 无比分时两侧进球列留空，中央分隔符列继续显示 `VS`。
3. 副行按半场比分自身的胜平负计算颜色，并对对应红、蓝、绿使用约 55% 透明度；不跟随全场赛果。
