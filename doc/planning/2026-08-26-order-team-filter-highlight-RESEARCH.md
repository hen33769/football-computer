# 订单队伍筛选命中高亮 Research

日期：2026-08-26

## 需求理解

- 在订单页输入“比赛队伍”筛选文字后，保留现有订单过滤行为。
- 对筛选结果卡片里的主队、客队名称，将与输入文字对应的部分显示为黄色底色。
- 未输入筛选文字、队名未命中或清除筛选后，不显示高亮。
- 统一“比赛队伍”和“比赛类型”的标题顶部位置，避免两组控件高度不同时因底部对齐产生上下错位。

## 当前实现

- `app/FootballApp.tsx` 使用 `orderTeamQuery` 保存输入值，通过 `orderContainsTeam` 过滤订单。
- `app/order-filters.ts` 会去除筛选文字首尾及内部空白，并按不区分大小写的方式匹配已投注比赛的主客队名称。
- 订单卡片的 `.order-match-entry-head > b` 当前直接渲染 `{match.home} VS {match.away}`，没有保留命中区间，因此无法添加局部背景色。
- `.order-filter-grid` 当前使用 `align-items: end`；“比赛类型”的标签区最小高度为 40px，而队伍输入框更矮，导致底边对齐后队伍标题向下偏移。
- 队伍筛选与比赛类型筛选的现有单测位于 `tests/calculator.test.ts`。

## 实现约束与风险

- 高亮匹配必须沿用现有筛选的大小写和空白归一化规则，避免“订单已被筛出但队名未高亮”的常见不一致。
- 分段逻辑应保留队名原文，只在 React 渲染时包裹命中片段，不能通过 HTML 字符串插入，以免引入转义或注入风险。
- 主队和客队分别渲染高亮；`VS` 分隔文字不参与高亮。
- 黄色样式需要在失败订单的灰色文字状态下仍然可见，同时继承当前文字颜色。
- 筛选标题应从同一网格行顶部对齐，不强制改变现有输入框或比赛类型标签的控件高度。
- 本次不改变订单数据结构、API、D1、筛选状态或云端查询。

## 预计影响文件

- `app/order-filters.ts`：增加队伍名称命中分段工具。
- `app/FootballApp.tsx`：在订单卡片主客队名称中渲染命中片段。
- `app/globals.css`：增加黄色高亮底色样式。
- `app/globals.css`：取消订单筛选网格的底部对齐，修复第二行标题错位。
- `tests/calculator.test.ts`：覆盖空白、大小写、多次命中和未命中分段。

## 验证重点

- 中文队名局部命中时只标黄对应文字，主客队均可命中。
- 英文字母大小写不同、输入包含首尾或内部空白时，高亮仍与过滤口径一致。
- 清空输入后所有黄色底色消失。
- 桌面端“比赛队伍”和“比赛类型”标题顶部位置一致，移动端单列布局保持正常。
- 桌面端与移动端订单卡片不因 `mark` 元素发生错位或溢出，控制台无错误。
