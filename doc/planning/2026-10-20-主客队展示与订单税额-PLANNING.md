# 主客队展示与订单税额 Planning

## 实施目标

- 使用必填的 `teamPosition: "home" | "away"` 收口 `TeamNameWithIcon` 与 `TeamNameWithAlias` 的主客队展示规则。
- 为订单增加税额字段，按整单税前奖金严格大于 10000 元时对全部奖金收取 20%，精确到分。
- 赛果判断时自动写入预计税额；手动税额可在任意订单状态修改，再次判断赛果时重新自动计算。
- 只有已结账且成功的订单税额参与账本。订单页统一展示税前奖金、税额和税后收入，并将“累计收入”改为“累计税后收入”。
- 回填符合条件的历史已结账订单，保持订单 JSON、D1 汇总列和财务统计一致。

## 数据结构与计算口径

- `SavedSlip`、`CompactOrder` 新增可选 `taxAmount?: number`，单位为元。
- `user_orders` 新增可空整数列 `tax_cents`，单位为分：
  - `NULL`：历史未计算或尚无税额值；
  - `0`：已计算或用户明确设置为 0；
  - 正整数：已保存税额。
- 新增统一税额工具函数：
  - 输入税前奖金和订单状态；
  - 整单税前奖金 `> 10000.00` 时返回奖金的 20%，按分舍入；
  - 自动判断阶段计算预计税额，不直接改变账本；
  - 账本只在 `settledAt` 存在且订单状态为 `success` 时扣除税额。
- 统一定义：
  - `grossIncome`：符合当前统计范围的税前奖金；
  - `tax`：范围内已结账且成功订单的税额；
  - `netIncome = grossIncome - tax`。

## 兼容策略

- 新订单始终保存明确税额；旧订单缺少字段时仍可解析。
- 迁移一次性回填符合条件的历史已结账订单；未结账订单在下一次赛果判断时生成预计税额，结账时兜底。
- `tax_cents` 与 `data_json.taxAmount` 由同一服务写入路径维护；读取历史异常数据时以独立列和统一计算规则修复，避免财务 SQL 与页面不一致。
- 导入文件版本暂不强制升级，新增字段保持可选；导出自然包含税额。

## 发布影响

- 新增数据库迁移并改变订单、财务统计和页面行为，正式发布时按 `minor` 版本处理。
- 部署前必须先在 `UPDATE.md` 写入完整变更，并确保 `package.json`、`package-lock.json`、`app/AppVersion.tsx` 和更新日志版本一致，再提交、推送和部署。
- 远端迁移和生产部署属于高风险操作，执行前需要确认目标环境与范围；本次实现阶段只进行本地迁移验证，除非开发者另行要求发布。
