# 订单财务趋势 Research

## 需求

- 在订单页“数据统计”标题后增加趋势图标，点击后打开弹窗。
- 弹窗使用 ECharts 展示支出、收入、利润三条非平滑折线，支持 legend、底部缩放条、图内拖动和鼠标滚轮缩放。
- 横轴显示日期（月日），纵轴显示金额。
- 新增趋势接口，支持可选 `start_date`、`end_date`（`yyyy-mm-dd`）；当前页面请求暂不传日期参数。

## 现有实现与数据流

- `app/FootballApp.tsx` 的订单页统计卡展示累计支出、累计收入与当前利润；云端数据来自 `FootballRoute.tsx` 加载的 `/api/finance`。
- `app/server/finance-service.ts` 的支出口径是所有 `payment_status = 'paid'` 订单的 `stake_cents`，收入是已结账订单的 `settled_prize_cents`，金额均以整数分存储。
- `user_orders` 有 `saved_at` 与 `settled_at`，没有独立 `paid_at`。订单支付后仍可能因结账等操作更新 `updated_at`，因此不能把 `updated_at` 当作稳定支付时间。
- 现有订单日期筛选使用 SQLite `date(saved_at, '+8 hours')`，即按中国时区业务日处理 ISO 时间。
- `user_finance_corrections` 只保存当前纠错值与最后更新时间，没有纠错流水，无法可靠还原历史日期上的纠错变化。
- 游客版订单与财务只存浏览器；账号版通过 D1 与 API 同步。因此图表需要同时支持云端接口数据和游客版当前订单的本地聚合。
- 项目当前未安装 ECharts。

## 数据口径

- 趋势按每日发生额展示，而不是累计曲线。
- 支出：当前仍为已支付状态的订单，将订单本金计入 `saved_at` 对应的中国时区日期。
- 收入：已结账订单，将结账奖金计入 `settled_at` 对应的中国时区日期。
- 利润：同一天的收入减支出。
- 财务纠错不纳入趋势；其历史不可从现有单行状态中准确重建。弹窗中应明确提示该口径。
- 无日期参数时返回全部有支出或收入事件的日期；有参数时分别限制事件日期。只返回有事件的日期，图表使用时间轴保留真实时间间隔。

## 接口设计

- `GET /api/finance/trend`
- 可选查询参数：`start_date`、`end_date`，严格校验 `yyyy-mm-dd` 且必须是真实日期；开始日期不得晚于结束日期。
- 响应：`{ points: Array<{ date, expense, income, profit }> }`，金额单位为元。
- 路由沿用云端账号鉴权；查询按用户隔离。
- 当前页面账号版固定调用无参数接口；游客版直接对浏览器中的完整订单集合按同口径聚合。

## 图表实现约束

- ECharts 通过动态导入在弹窗首次打开时加载，避免订单页首屏同步引入完整图表运行时。
- 三条 `line` series 均设置 `smooth: false`；颜色为支出红、收入绿、利润橙。
- 同时配置 `inside` 与 `slider` 两种 `dataZoom`：图内拖动平移、滚轮缩放，并保留可拖动的底部缩放条。
- 使用 `time` 类型横轴，标签与 tooltip 将 `yyyy-mm-dd` 显示为 `MM-DD`；纵轴和 tooltip 格式化为人民币金额。
- chart 在容器尺寸改变时 `resize`，弹窗关闭/组件卸载时 `dispose`。

## 风险与验证重点

- `saved_at` 表示订单日期而非真实支付时间；这是现有模型能稳定提供的支出归属日期。
- 删除已支付/已结账订单会相应移除历史趋势事件，与当前累计统计口径一致。
- 纠错不进入趋势，因此趋势各日之和可能与包含纠错的统计卡总额不同。
- 验证接口日期边界、用户隔离与金额分/元转换；验证无数据、加载失败、弹窗重开、桌面/移动尺寸、legend 和三种缩放交互。
