# 订单财务趋势 Research

## 需求

- 在订单页“数据统计”标题后增加趋势图标，点击后打开弹窗。
- 弹窗使用 ECharts 展示当日支出、当日收入、当日利润以及累计支出、累计收入、累计利润六条非平滑折线，支持 legend、底部缩放条、图内拖动和鼠标滚轮缩放。
- 累计三条线默认显示；当日三条线使用对应累计线的浅色并默认隐藏，可通过 legend 开启。
- 累计支出、累计收入分别以支出纠错、收入纠错为初始值；tooltip 必须能命中日期范围内的每个自然日，而不只在发生金额变化的日期出现。
- 横轴显示日期（月日），纵轴显示金额。
- 新增趋势接口，支持可选 `start_date`、`end_date`（`yyyy-mm-dd`）；当前页面请求暂不传日期参数。

## 现有实现与数据流

- `app/FootballApp.tsx` 的订单页统计卡展示累计支出、累计收入与当前利润；云端数据来自 `FootballRoute.tsx` 加载的 `/api/finance`。
- `app/server/finance-service.ts` 的支出口径是所有 `payment_status = 'paid'` 订单的 `stake_cents`，收入是已结账订单的 `settled_prize_cents`，金额均以整数分存储。
- `user_orders` 有 `saved_at` 与 `settled_at`，没有独立 `paid_at`。订单支付后仍可能因结账等操作更新 `updated_at`，因此不能把 `updated_at` 当作稳定支付时间。
- 现有订单日期筛选使用 SQLite `date(saved_at, '+8 hours')`，即按中国时区业务日处理 ISO 时间。
- `user_finance_corrections` 只保存当前纠错值与最后更新时间，没有纠错流水，无法可靠还原历史日期上的纠错变化。
- 游客版订单与财务只存浏览器；账号版通过 D1 与 API 同步。因此图表需要同时支持云端接口数据和游客版当前订单的本地聚合。
- 项目已经安装 ECharts，并在趋势弹窗打开时动态加载。

## 数据口径

- 当日支出：当前仍为已支付状态的订单，将订单本金计入 `saved_at` 对应的中国时区日期。
- 当日收入：已结账订单，将结账奖金计入 `settled_at` 对应的中国时区日期。
- 当日利润：同一天的当日收入减当日支出。
- 累计支出与累计收入分别以当前支出纠错、收入纠错作为初始值，再逐日累加订单支出和结账收入；累计利润为累计收入减累计支出。
- `user_finance_corrections` 没有历史流水，因此当前纠错值只能作为整条累计曲线的初始基线，不能还原纠错实际修改日的阶跃变化。
- 无日期参数时从首个事件前一天（用于显示纠错初始值）到最后事件返回连续自然日；只有纠错而没有订单事件时返回纠错更新时间所在日。有日期参数时按范围返回连续自然日，并把开始日前的订单事件预先累加到累计值中。
- 没有支出或收入的日期也返回当日金额为 0 的点，保证 category 横轴的每个日期都可触发 axis tooltip。

## 接口设计

- `GET /api/finance/trend`
- 可选查询参数：`start_date`、`end_date`，严格校验 `yyyy-mm-dd` 且必须是真实日期；开始日期不得晚于结束日期。
- 响应：`{ points: Array<{ date, expense, income, profit, cumulativeExpense, cumulativeIncome, cumulativeProfit }> }`，金额单位为元；前三个金额字段表示当日值。
- 路由沿用云端账号鉴权；查询按用户隔离。
- 当前页面账号版固定调用无参数接口；游客版直接对浏览器中的完整订单集合按同口径聚合。

## 图表实现约束

- ECharts 通过动态导入在弹窗首次打开时加载，避免订单页首屏同步引入完整图表运行时。
- 六条 `line` series 均设置 `smooth: false`；累计支出红、累计收入绿、累计利润橙，当日线使用各自对应的浅色。
- legend 默认选中累计三条线、取消选中当日三条线。
- 同时配置 `inside` 与 `slider` 两种 `dataZoom`：图内拖动平移、滚轮缩放，并保留可拖动的底部缩放条。
- 使用连续自然日数据的 `category` 横轴，轴指针开启吸附，标签与 tooltip 将 `yyyy-mm-dd` 显示为 `MM-DD`；这样无需放大即可在任一日期触发 tooltip。纵轴和 tooltip 格式化为人民币金额。
- chart 在容器尺寸改变时 `resize`，弹窗关闭/组件卸载时 `dispose`。

## 风险与验证重点

- `saved_at` 表示订单日期而非真实支付时间；这是现有模型能稳定提供的支出归属日期。
- 删除已支付/已结账订单会相应移除历史趋势事件，与当前累计统计口径一致。
- 当前纠错值只作为累计初值；没有纠错流水时无法表现历史纠错修改过程，这是现有数据模型的明确限制。
- 连续日期数量设置上限，避免异常超长范围生成过多前端数据点。
- 验证接口日期边界、开始日前事件预累加、用户隔离与金额分/元转换；验证六条线的 legend 默认显隐、空白日期 tooltip、无数据、加载失败、弹窗重开、桌面/移动尺寸和三种缩放交互。
