# 订单奖金范围与比赛复制 Research

日期：2026-11-13。

## 现有实现与数据流

- `app/calculator.ts` 的 `calculatePrizeRange` 接收比赛、串关、倍数与命中项。订单卡片及明细直接调用，未传入失败场次、已判断赛果或结账快照。
- `scenarioWinningOdds` 一旦某场存在命中项，就固定整场，导致同场其他未确认玩法被忽略；没有命中项的已失败比赛仍被当作未知比赛。
- 极值当前先按每场命中赔率之和选情景，再计算整单，遇到逐注封顶与舍入时不能保证上下限。
- `SavedSlip` 已包含 `failedMatches`、`resultValues`、`resultScores`、`settledAt`、`settledPrize`，云端紧凑订单转换保留这些字段，无需数据库迁移或 API 变化。
- 明细中命中及失败有未保存草稿；手动改结果时当前保留旧 `resultValues/resultScores/resultOdds`，接入赛果约束前需同步清理该场旧快照。
- `app/match-format.ts` 统一生成复制行，投注页 `copyMatchesForDate` 在日期行后逐行调用。比赛本身已有 `weekday/code`。

## 修复口径

- 保留中奖最低值排除 0、税前奖金、订单赔率快照、逐注封顶及原始出票份数；失败比赛不能从订单结构删除，否则会改变跨玩法出票份数。
- 按玩法约束枚举一致的赛果，已确认命中仅固定对应玩法；失败整场固定不中奖，完整赛果使范围收敛。
- 已结账直接使用保存的税前奖金（含 0）；历史缺少结账奖金时回退当前命中奖金。
- 极值在实际可行情景中求取，用赔率向量支配关系及逐串关缓存的条件奖金上下界减少组合量，避免用单场赔率和代替实际奖金；极低赔率舍入为零时，最低正奖金搜索保留被支配情景。
- 订单卡片及明细同用订单级计算；金额确定后显示单值，失败显示 ¥0.00。
- 复制行使用 `周三 001 ｜ xxx vs ddd （客让 1）`；保留日期行及盘口缺失的降级。

## 风险与验证

- 覆盖部分失败但仍可中奖、跨玩法出票重复份数、部分赛果、人工改判、结账快照和封顶反例。
- 用独立的小规模赛果穷举核对上下限，增加八场混合玩法性能检查。
- 浏览器验证订单卡片／明细、未保存命中／失败切换及复制结果，覆盖桌面和移动端。
- 保留当前工作区已有前瞻标题及 CSS 改动；本任务不发布。

## 补充：卡片完整奖金范围副行

- 用户要求在订单卡片右侧奖金主行下，以浅色副行显示完整奖金范围。
- 主行继续使用 `calculateOrderPrizeRange`；副行调用现有 `calculatePrizeRange(matches, passes, multiple)`，不传入命中、失败、赛果或结账约束。
- 两行均使用当前订单赔率快照、税前奖金和最低正奖金口径；已失败、已结账也保留完整理论范围便于对照。
- 在现有标题右侧增加纵向容器，保持右对齐；副行标注“完整”并使用较小字号和浅色，无接口、数据或迁移变化。
- 后续调整：未确定任何赛果时不显示副行，也不重复计算完整范围。有已选比赛的命中、失败标记、任一有效玩法赛果或已知比分时显示；空赛果对象与空命中值不视为已确定。按用户明确口径，结账状态不独立触发副行。
