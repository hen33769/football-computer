# 比赛类型筛选无效选项清理 Planning

日期：2026-08-25

关联 Research：`doc/planning/2026-08-25-league-filter-selection-pruning-RESEARCH.md`

## 目标

- 当投注页或订单页的比赛类型选项变化时，只保留仍存在于最新选项中的已选类型。
- 防止不可见的历史选择继续参与过滤，确保用户能看到新筛选条件下的预期比赛或订单。
- 让投注页和订单页复用同一条选择收敛规则并具备单元测试。

## 实施方案

1. 在 `app/order-filters.ts` 增加纯函数，将已选比赛类型与最新可用类型取交集；没有失效值时返回原数组。
2. 投注页从 `availableLeagueOptions` 建立最新可用类型集合，首轮渲染即用交集后的选择过滤比赛，并在选项集合变化后移除状态中的失效值。
3. 订单页提前从当前订单生成可用比赛类型集合，以交集后的选择过滤订单，并在订单导致选项变化后移除失效值。
4. 在 `tests/calculator.test.ts` 增加交集规则测试，随后运行 diff 检查、测试、Lint 和生产构建。
5. 启动本地页面，用桌面端和移动端验证两页筛选切换、标签状态、空结果恢复和控制台错误。

## 接口、兼容与发布影响

- 不新增或修改 API、数据结构、D1 迁移及持久化键。
- 仍可用的历史选择保持不变；只有已经无法通过页面标签取消的失效类型会被移除。
- 本次属于小范围筛选缺陷修复；实现完成后开发者要求提交、推送和部署，因此按 patch 发布为 `v1.11.1`，并在同一发布提交中同步版本面和 `UPDATE.md`。
- 本次没有数据库变化；为保护正式 D1 和订单数据，发布过程不执行远端迁移或订单重写。

## 实施结果

- `retainAvailableLeagueNames` 统一执行“已选类型与最新选项取交集”，在所有值仍有效时返回原数组。
- 投注页以当前日期、销售状态和比赛数据生成的选项集合为准；订单页以当前加载订单中实际已投注比赛生成的选项集合为准。
- 两页在选项变化后的首轮渲染就使用有效选择进行过滤，并通过限定 Effect 清除状态中的失效值，避免隐藏筛选和结果闪烁。
- 仍在新选项集合中的已选类型保持原顺序和选中状态；未改动 API、D1 或订单数据结构。
