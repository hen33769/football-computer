# 投注页比赛队伍过滤 Planning

关联 Research：`doc/planning/2026-10-08-投注页比赛队伍过滤-RESEARCH.md`

## 实施方案

1. 扩展公共队伍名称索引，使任意官方名称除了解析展示主名、别称和图标，还能取得同组全部规范化搜索名称。
2. 在前端筛选工具中增加比赛队伍匹配函数：空查询直接通过，非空查询同时检查主客队原名及对应名称组的全部名称。
3. 在投注页增加 `matchTeamQuery` 会话状态，并将其与日期、销售状态和比赛类型按 AND 组合；联赛选项集合保持现有计算边界，不被队伍查询收窄。
4. 在日期和比赛类型之间增加独立输入行，支持搜索图标、清除按钮、加载禁用和无障碍标签；“清除筛选”同步清空队伍查询。
5. 让投注比赛卡片接收查询文字：可见文字精确命中时高亮对应片段，只命中未激活历史名称时高亮整侧当前展示队名。
6. 补充纯函数回归测试，并完成桌面端、390×844 移动端和控制台验证。

## 接口与数据兼容

- 不新增或修改 API、D1 表、迁移、比赛结构或订单结构。
- 继续复用正式版和 standalone 已加载的公共队伍名称组；过滤不触发网络请求。
- 筛选只控制比赛卡片可见性，不删除已选投注项、不重写主客队名称，也不持久化查询文字。
- 订单页队伍过滤保持现状，本次只调整投注页。

## 高亮规则

- 使用与别称搜索相同的 NFKC、大小写和空白归一化规则定位文字，同时保留原始显示字符。
- 主名或当前显示别称包含查询时，只高亮对应可见片段。
- 查询通过未激活历史名称命中时，当前卡片没有该文字可供片段高亮，因此高亮该侧完整的主名与显示别称。
- 主客队只有实际命中的一侧高亮；空查询不增加任何高亮样式。

## 验证方式

- 纯函数测试覆盖空查询、原始主客队、激活名称、未激活历史名称、部分匹配、NFKC/大小写/空白差异和无匹配。
- `npm test`、`npm run lint`、`npm run build` 和 `npm run build:html`。
- 桌面端验证输入框位置、组合筛选、具体文字高亮、历史名称整侧高亮、清除恢复和已选投注保留。
- 390×844 移动端验证独立单列输入、清除操作、卡片高亮和无横向溢出，并检查浏览器控制台。

## 发布影响

- 这是新增投注页筛选能力，正式发布时应按 `minor` 更新版本。
- 当前未收到提交、推送或部署要求，不修改 `UPDATE.md` 和版本号。
