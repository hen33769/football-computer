# 订单按状态撤回 Planning

## 实施步骤

- [x] 扩展订单模型，记录支付前的倍率锁定状态，并新增受校验的 `withdraw` 批量操作。
- [x] 在服务端按当前订单状态分别回滚结账或支付，保持并发校验与批量原子写入语义。
- [x] 调整订单卡片：已结账和已支付未结账订单都显示同一个“撤回”按钮，确认文案与账本变化随状态切换。
- [x] 补充服务端测试，覆盖撤回结账、撤回支付和不可撤回状态。
- [x] 运行相关测试、完整测试、lint 与构建，并记录结果。

## 接口与数据结构

- `BulkOrderOperation` 新增 `withdraw`，仍通过 `/api/orders/bulk` 提交。
- `SavedSlip` 与 `CompactOrder` 新增可选布尔字段 `oddsLockedBeforePayment`，仅写入订单 JSON。
- 不新增或修改 D1 迁移。

## 兼容策略

- 历史订单缺少 `oddsLockedBeforePayment` 时，撤回支付默认恢复为倍率未锁定。
- 保留现有 `/api/orders/:id/withdraw-settlement` 接口语义，新的页面流程使用带服务端状态判定的批量撤回操作。
- 前后端复用同一个状态回退函数，撤回不修改投注、赔率数值或赛果。历史已结账订单保留原支付状态。
- 操作返回值保留实际提交的订单及版本，即使订单离开当前筛选列表，明细仍能取得最新状态。

## 验证方式

- 单元测试验证两类撤回的最终状态、倍率锁定恢复以及非法状态整批不写入。
- 运行 `npm test`、`npm run lint`、`npm run build`。
- 启动页面后用桌面与移动视口核对按钮组合、确认文案与控制台错误。
