# 收入纠错税额 Planning

日期：2026-10-29。状态：实现与本地验证完成，已确认纳入 v1.40.0 发布。

关联 Research：`doc/planning/2026-10-29-收入纠错税额-RESEARCH.md`。

## 已确认口径

- 纠错类型文案统一为“支出／收入”。
- 收入金额表示税前收入差值；税额表示带正负号的税额差值。
- 税后净差值 = 税前收入差值 − 税额差值。
- 允许收入差值为 0、只纠正税额；收入和税额同时为 0 时拒绝。
- 税额不自动套用订单税率；最终累计税前收入、税额、税后收入均不得小于 0。
- 旧收入纠错和旧备份按税额 0 兼容，历史税后收入与利润不改变。

## 数据与接口方案

- 新增 `0014_finance_correction_tax.sql`，给纠错流水增加税额差值及税额累计 before／after，给财务汇总增加收入纠错税额；不改写 0013。
- 保留 `delta_cents` 为税后净影响。收入税前差值由 `delta_cents + tax_delta_cents` 推导；支出税额恒为 0。
- POST 新增 `amountDeltaCents` 和 `taxDeltaCents`；旧 `deltaCents` 请求按税额 0 兼容一个版本。
- Finance 响应增加收入纠错税前、纠错税额、累计税前和累计税额，同时保留旧订单税额及税后纠错字段。
- 完整备份升级 v7；v5／v6 导入时补税额 0。游客账本升级 v3，并从 v2 幂等迁移。

## 验证重点

- 收入 `+200`、税额 `+20` 后，税前增加 200、税额增加 20、税后和利润增加 180。
- 对上述记录补差收入 `-20`、税额 `-2` 后，税前累计 180、税额累计 18、税后累计 162。
- 收入 0、税额正负非零均可保存；两者同时 0 拒绝。
- 最终累计税前、税额或税后任一小于 0 时整笔拒绝且 revision 不增加。
- 旧流水、v5／v6 备份和游客 v2 迁移后税额为 0，原净收入不变。
- requestId 与稳定来源 ID 的内容比较包含税额，重复请求不重复入账，不同税额冲突。
- 有日期税额进入对应日，无日期税额进入初值；累计利润始终使用税后收入。
